================================================================================
ML-ENHANCED UPWORK JOB SCORER - PHASE-BY-PHASE DEVELOPMENT PLAN
================================================================================

Project: Chrome Extension with Machine Learning for Intelligent Job Scoring
Start Date: December 3, 2025
Tech Stack: React 18, TypeScript, Webpack 5, TensorFlow.js, Chrome Manifest V3

================================================================================
PHASE 1: FOUNDATION & BASIC CONTENT SCRIPT (Week 1-2)
================================================================================

Objective: Build working rule-based job scorer extension

Tasks:
1. Initialize new project structure
   - Create TypeScript + React 18 + Webpack 5 boilerplate
   - Set up Manifest V3 configuration for https://www.upwork.com/*
   - Configure hot reload development environment
   - Add ESLint + Prettier for code quality
   - Initialize Git repository with .gitignore

2. Implement DOM extraction engine
   - Build src/content/dom-extractor.ts for job card scraping
   - Use Upwork's data-test selectors (proposals, payment, spending, ratings, time, description)
   - Integrate Arrive.js or MutationObserver for dynamic content
   - Create TypeScript interfaces for JobData structure
   - Add error handling for missing fields with fallback defaults

3. Create rule-based scoring system
   - Port helper functions to src/services/rule-scorer.ts with TypeScript
   - Implement 5 scoring factors:
     * Proposals score (less competition = higher)
     * Payment verification (10 or 0 points)
     * Client spending (0-10 scale based on amount)
     * Client rating (rating × 2)
     * Posting time (fresher = higher)
   - Add basic regex spam detection (phone/email patterns)
   - Calculate averaged final score (0-10 scale)

4. Build visual badge system
   - Create src/content/badge-renderer.ts for score display
   - Implement color-coded styling:
     * Green: 7.0-10.0 (excellent)
     * Yellow: 3.0-6.9 (decent)
     * Red: 0.0-2.9 (poor)
   - Add spam warning overlay with red background
   - Position badges non-intrusively (top-right corner)
   - Ensure no duplicate badges on re-renders

CHECKPOINT: Extension loads on Upwork, detects jobs dynamically, displays 
accurate rule-based scores with color coding, flags spam jobs. Test with 20+ 
real job listings to verify extraction accuracy.

================================================================================
PHASE 2: ML INFRASTRUCTURE & MODEL PIPELINE (Week 3-4)
================================================================================

Objective: Establish TensorFlow.js infrastructure and training environment

Tasks:
1. Set up TensorFlow.js in service worker
   - Install @tensorflow/tfjs@^4.14.0, @tensorflow/tfjs-backend-webgl
   - Create src/background/ml-engine.ts with model loader class
   - Implement lazy loading with IndexedDB caching for model weights
   - Add WebGL backend initialization with CPU fallback
   - Create message passing between content script and service worker

2. Build feature engineering pipeline
   - Create src/services/feature-extractor.ts
   - Normalize structured features (0-1 scale for spending, proposals, ratings)
   - Extract text statistics (word count, sentence count, avg word length)
   - Implement basic text preprocessing (lowercase, punctuation removal, tokenization)
   - Create feature vector builder combining structured + text features
   - Add feature validation with type guards

3. Develop Python training environment
   - Set up training/ directory with requirements.txt:
     * tensorflow
     * pandas
     * scikit-learn
     * tensorflowjs
   - Create training/collect_data.py for manual job labeling
   - Build data preprocessing pipeline matching browser feature extraction
   - Implement train/validation split utilities
   - Create model export script with TensorFlow.js conversion and quantization

4. Create initial training dataset
   - Manually label 100 jobs:
     * 50 good quality jobs
     * 30 mediocre jobs
     * 20 poor/spam jobs
   - Use CSV format with columns: job_id, description, structured_features, quality_label
   - Validate data quality and balance
   - Document labeling guidelines in training/LABELING_GUIDE.md
   - Store anonymized data in training/data/initial_dataset.csv

CHECKPOINT: TensorFlow.js loads successfully in service worker, feature 
extraction converts job data to ML-ready format, Python training environment 
can load data and export dummy models, model loading latency <3s. No ML 
predictions yet, just infrastructure validation.

PHASE 3: SPAM DETECTOR MODEL (Week 5-6)
================================================================================

Objective: Deploy first ML model for spam detection

Tasks:
1. Train lightweight spam classifier
   - Build LSTM/GRU model in training/train_spam_detector.py
   - Target <1MB model size (quantized)
   - Use labeled spam examples (phone/email + manual labels)
   - Implement character-level or word-level embedding (128 dims)
   - Train for binary classification (spam vs legitimate)
   - Achieve 85%+ accuracy on validation set
   - Export quantized model to src/models/spam/

2. Integrate spam model in extension
   - Load spam model in service worker src/background/ml-engine.ts
   - Implement async prediction function accepting feature vector
   - Add confidence threshold (>0.7 = spam)
   - Create fallback to regex if model fails
   - Cache predictions per job ID for 24h

3. Update UI with ML spam warnings
   - Modify badge renderer to show "AI-DETECTED SCAM" label
   - Add confidence percentage display
   - Enhance visual warning (stronger red background, warning icon)
   - Add tooltip explaining detection reasoning
   - Compare ML vs regex spam detection side-by-side
   - Log false positives for model improvement

4. Collect spam detection metrics
   - Add anonymous analytics to src/services/analytics.ts
   - Track: prediction time, memory usage, confidence distribution
   - Create feedback mechanism ("Report false positive" button)
   - Store feedback in chrome.storage.local for future training
   - Generate weekly reports on detection accuracy

CHECKPOINT: ML spam detector runs in production, flags scams with higher 
accuracy than regex, shows confidence scores in UI, completes predictions in 
<50ms per job, feedback collection system works. Test with 50 jobs including 
known scams.

================================================================================
PHASE 4: JOB QUALITY CLASSIFIER (Week 7-9)
================================================================================

Objective: Deploy quality assessment model for comprehensive job scoring

Tasks:
1. Expand training dataset for quality scoring
   - Label 300+ additional jobs on 3-tier scale (excellent/good/poor)
   - Use proxy labels from rule-based scores as weak supervision
   - Manually verify 100 high-confidence examples
   - Balance dataset across quality tiers and job categories
   - Augment with synthetic examples (paraphrasing, back-translation)

2. Train quality assessment model
   - Integrate @tensorflow-models/universal-sentence-encoder
   - Build training/train_quality_model.py
   - Use USE embeddings for description + structured features
   - Build shallow neural network (Dense layers) on top
   - Target 5-10MB quantized size
   - Achieve MAE <0.8 on 0-10 scale
   - Export to src/models/quality/

3. Implement ensemble scoring system
   - Create src/background/ensemble-scorer.ts
   - Combine ML (60%) and rules (40%)
   - Add confidence-aware weighting (higher confidence = more ML weight)
   - Implement spam penalty (cap ML score at 3 if spam detected)
   - Calculate prediction uncertainty using model variance
   - Provide score breakdown for transparency

4. Enhance badge UI with ML insights
   - Update badges to show dual scores (ML + Rule-based)
   - Add visual comparison between scores
   - Add confidence indicator (high/medium/low with color coding)
   - Create expandable details panel showing feature importance
   - Implement smooth transitions for score updates
   - Add "Powered by AI" badge with info tooltip

CHECKPOINT: Quality classifier produces accurate 0-10 scores, ensemble 
outperforms rule-based by 15-20% (user validation), UI clearly shows ML vs 
traditional scoring, inference stays <100ms per job, model handles edge cases 
gracefully. Test with 100 diverse jobs.

PHASE 6: ADVANCED FEATURES & PERSONALIZATION (Week 12-14)

================================================================================
KEY TECHNICAL DECISIONS
================================================================================

ML Framework: TensorFlow.js 4.x
- Best browser support, NLP tooling, production-ready

Deployment: Hybrid (bundled core + CDN optional)
- Balance size, performance, privacy

Model Training: Python (TF/Keras) → convert to TFJS
- Leverage Python ecosystem, deploy to browser

Where to Run: Service Worker (Manifest V3)
- Shared across tabs, doesn't block UI

Model Size: 5-10MB (quantized)
- Acceptable for extension, <50ms inference

Data Strategy: Bootstrap with proxy labels + user feedback
- No external data needed initially

Scoring Approach: Ensemble (rule-based + ML)
- Best of both worlds, gradual migration
